# Instrucción Obligatoria de Documentación - Proyecto supaSPH-QR

## 📋 REGLA FUNDAMENTAL

**SIEMPRE** que realices cualquier modificación, creación o actualización de componentes en la base de datos (tablas, funciones, triggers, vistas, etc.), DEBES documentar los cambios siguiendo estrictamente la guía de documentación establecida.

## 🔥 PASOS OBLIGATORIOS POST-MODIFICACIÓN

Después de completar CUALQUIER cambio en la base de datos, debes realizar SIEMPRE los siguientes pasos en orden:

### 1. Documentar el componente modificado
- Actualizar el encabezado del archivo SQL con fecha y hora actual
- Verificar que la documentación interna cumpla con todos los estándares

### 2. Actualizar README.md de la carpeta afectada
- Documentar los cambios realizados
- Actualizar el flujo de procesamiento si es necesario
- Agregar notas sobre las actualizaciones
- Actualizar el estado actual de componentes

### 3. Actualizar script de instalación
- Modificar la fecha y hora
- Agregar notas sobre los cambios realizados
- Verificar que el orden de instalación sea correcto

### 4. Actualizar README.md general del proyecto
- Modificar la descripción de los componentes afectados
- Agregar el cambio al registro de cambios

## 🚫 EXCEPCIONES PROHIBIDAS

ESTÁ PROHIBIDO:
- Realizar cambios sin documentar
- Declarar tarea completada sin actualizar la documentación
- Omitir cualquiera de los pasos obligatorios
- Usar frases como "ya está documentado" sin verificarlo

## ✅ VERIFICACIÓN FINAL

Antes de declarar una tarea como completada, verifica que:
- [ ] El archivo SQL modificado tiene documentación completa
- [ ] El README.md de la carpeta está actualizado
- [ ] El script de instalación está actualizado
- [ ] El README.md general está actualizado
- [ ] El registro de cambios incluye la modificación

## 🎯 FRASE CLAVE

**"LA DOCUMENTACIÓN ES PARTE OBLIGATORIA DEL DESARROLLO, NO UN OPCIONAL"**
